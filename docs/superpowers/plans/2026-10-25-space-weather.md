# Space Weather Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/space` page fed by NOAA SWPC through our own Postgres store, per `docs/superpowers/specs/2026-10-25-space-weather-design.md`.

**Architecture:** Server jobs poll eleven SWPC files into one tall samples table and three record tables; two reads serve the latest readings and a thinned window; the web gets a fourth page with tiles, a shared-axis stack and a rail.

**Tech Stack:** Fastify, zod, Drizzle (Postgres), Vue 3, d3-scale, Vitest.

## Global Constraints

- Branch `space-weather`; never commit to `main`.
- 100% coverage on `apps/server/src`, `packages/shared/src`, `apps/web/src`; no `as` casts to silence nullability, no `!`.
- Migrations generated by drizzle-kit, never hand-edited.
- Gate before every push: `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test:coverage && pnpm build`.
- Response types derive from domain types through `Json<T>`.
- `raw` never leaves the server (no raw SWPC payloads in responses).
