# Aurora Oval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two polar aurora maps with a 72-hour scrub on the Space page, fed by stored OVATION Prime frames, per `docs/superpowers/specs/2026-10-25-aurora-overlay-design.md`.

**Architecture:** The five-minute `space_fast` job stores each OVATION frame as a 65,160-byte grid with its times and hemispheric power; two reads serve the index and one frame; the web contours the grid into five probability bands and projects them onto two azimuthal maps with the night side shaded.

**Tech Stack:** Fastify, zod, Drizzle (bytea), Vue 3, d3-geo, d3-contour, Vitest.

## Global Constraints

- Branch `aurora-overlay`; never commit to `main`.
- 100% coverage on `apps/server/src`, `packages/shared/src`, `apps/web/src`; no `as` casts to silence nullability, no `!`.
- Migrations generated by drizzle-kit, never hand-edited.
- Gate before every push: `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test:coverage && pnpm build`.
- Response types derive from domain types through `Json<T>`; the grid is the one declared exception (base64 string).
- Copy never says "aurora visible here"; always observation and forecast times.
