# Tectonic Desk

Earth-sciences dashboard for a reader with formal geology training. Earthquakes now, volcanoes next, space weather considered later. Write copy and drill-down depth for a peer, not a novice.

## Repo rules

- Branch workflow: `main` is the base and is never committed to directly. Each change goes on its own branch, is pushed, and reaches `main` through a pull request (CI runs once per PR, on the merge commit, and gates the merge). Deploying is a pull request from `main` into `release`; merging it triggers the Deploy workflow, which runs its own check before building images.
- `quake/` is the frozen prototype. Never modify it. Its `CLAUDE.md` holds the verified focal-mechanism conventions and USGS endpoint notes; consult it, do not edit it.
- pnpm workspace: `apps/server` (Fastify, Drizzle, Postgres, USGS ingest, API), `apps/web` (Vue 3 + Vite), `packages/shared` (domain and API types, mechanism math, no third-party runtime deps).
- Specs live in `docs/superpowers/specs`, plans in `docs/superpowers/plans`. Each sub-project (Foundation, Ingest, API, Front end) gets its own.
- TypeScript strict, ESM, NodeNext. Imports of local files use the `.js` extension.
- Repositories are plain functions taking a `Db` first. No classes, no singletons. `Db` accepts both the pool handle and a transaction.
- Coverage thresholds are 100% on `apps/server/src`, `packages/shared/src` and `apps/web/src`. Add a test rather than lowering them. Entry points (`index.ts`, `*-cli.ts`, `main.ts`) are excluded. The server integration suites run on a Testcontainers Postgres: without Docker they skip on a developer machine, but in CI (`CI=true`) `dockerAvailable` retries and then throws, because skipped suites only surface as a coverage failure.
- Postgres dev container is on host port 5433 (5432 is taken on the dev machine).
- Migrations are generated by drizzle-kit into `apps/server/drizzle/migrations` and checked in. Never hand-edit a generated migration; change the schema and regenerate.
- Lint is typescript-eslint strict + stylistic, type-checked. No `as` casts to silence nullability and no `!` assertions; restructure instead.

## Ingest

- Runs inside the server behind `INGEST_ENABLED` (default true). Set it to `false` for a second API instance or when running against the dev DB without polling.
- Ingest code takes an `IngestContext { db, usgs, log, now }`; tests inject a stub USGS client (`test/support/usgs-stub.ts`) and a fixed clock.
- USGS feed properties are numbers; product properties are strings. Parsers live in `apps/server/src/usgs/parse.ts`. Fixtures under `apps/server/test/fixtures/usgs` are trimmed real responses from 2026-10-13.
- Mechanism conventions from `quake/CLAUDE.md` still apply: percent-double-couple stored as a fraction, planes reconstructed from T and P axes when absent and flagged `planes_reconstructed`.
- Backfill: `ingest/backfill.ts` walks `windowsBetween(from, to)` (`ingest/windows.ts`: UTC calendar months from 1970, years before; never clipped) newest first, skips windows `windowCovered` in `catalog_windows`, and records a window only when it ended `SETTLE_DAYS` (30) before the run. Page requests go through `withRetry` (`ingest/retry.ts`, 429/5xx/network, 5 attempts doubling from 5 s) and an injectable `sleep`. `upsertEvents` deletes rows named in an incoming event's `ids` aliases (`merged`) and bumps `last_seen` at most hourly. CLI flags are parsed by the pure `ingest/cli-args.ts`.

## API

- Response types live in `packages/shared/src/api.ts`, derived from the domain types through `Json<T>` (dates become ISO strings). Add a field to the domain type and the DTO follows; never hand-copy a DTO.
- `raw` never leaves the server except as `usgs` on `GET /api/events/:id`.
- Volcanoes: `src/geo/gvp.ts` builds the reference files from GVP's WFS (`geo:volcanoes`); `src/volcano/{schema,client,parse}.ts` read USGS HANS, GeoNet and the weekly-report RSS without merging agency scales; `repositories/volcano-status.ts` stores one row per status change and treats a volcano's first row as a baseline, not a change; `ingest/volcanoes.ts` runs as extra scheduler jobs (`jobs` option, own lanes) and fills elevated USGS rows' `synopsis` from the HANS notice text (`noticeSynopsis`, one fetch per notice). Routes in `routes/volcanoes.ts`. The weekly report feed (volcano.si.edu) refuses non-browser clients: `fetchWeeklyReport` tries the feed, then the `feeds` branch copy that `pnpm feeds:mirror` (`scripts/weekly-report-mirror.js`, local Chrome, a residential address) refreshes (`WEEKLY_REPORT_MIRROR_URL`); datacenter addresses are refused even in a browser; items name the volcano in the guid (`#vn_<number>`) and the kind of report in the title.
- Route handlers throw `HttpError` (`badRequest(issues)`, `notFound()`); the app-level handler renders `{ error, issues? }`. Query parsing goes through `parseOrThrow` in `src/api/schemas.ts`.
- Every successful response sets `Cache-Control` via `cacheFor(reply, seconds)`.
- Aggregates (`/api/events/count|summary|grid`) and `/api/catalog/coverage` take the list filters through `parseEventsFilter` (a strict object, so `limit` is a 400 there); `summarizeEvents` and `gridEvents` group by ordinal (`group by 1`) so parameterised expressions match.
- `@fastify/rate-limit` runs globally (`RATE_LIMIT_MAX` per `RATE_LIMIT_WINDOW_MS`, 0 disables) and
  answers in the `{ error }` shape; `TRUST_PROXY` makes it key on X-Forwarded-For behind nginx, which
  also carries a `limit_req` zone in `deploy/nginx.conf`. Tests pass small limits through `buildApp`.
- `buildApp({ db, now, geoDir })`: inject `now` in tests for deterministic default windows and stamps.
- Geo files under `apps/server/data/geo` are copies of the prototype's; regenerate, never edit.
- nginx will serve `apps/web` and proxy `/api`; the server has no CORS, static, or compression plugins.

## Front end

- `apps/web`: Vue 3 + Vite, vue-router. Templates render the SVG; d3-geo, d3-scale and d3-zoom are libraries (d3-selection and d3-transition only attach the zoom behaviour). No d3-axis: `ChartAxes.vue` renders ticks from `ticksOf(scale, count)`.
- State is a `Catalog`, a `StatusPoll`, a `Clock` and a `Theme`, created in `App.vue` and provided under the keys in `src/lib/keys.ts`. Tests mount components with `mountWith(component, ctx)` from `test/support/mount.ts`; `makeContext()` builds a loaded catalog over `fakeApi()`.
- Region and selection live in the route (`/:region`, `?event=id`); components call the injected `SELECT` function, never the router.
- Mechanism math (tensor, axes, classification, `planesOf`) is in `packages/shared/src/mechanism`; `src/lib/beachball.ts` only rasterises. Tests stub the canvas with `stubCanvas()`.
- Pages: `App.vue` is the shell (header, status line, shared stores, footer, route sync) and renders `EarthquakesPage`, `VolcanoesPage` or `ActiveEarthPage` from the route's `meta.page` (`earthquakes`, `volcanoes`, `active`; paths `/earthquakes/:region?`, `/volcanoes/:region?`, `/active/:region?`, `/` redirects to `/active` and a bare `/:region` to the earthquakes page for old links; `router.ts` has `pageOf`, `pagePath(page, region)` and `hasVolcanoes(page)`, which says which pages load the volcano store and render `VolcanoDetail`). Selecting an event drops `?volcano` and selecting a volcano drops `?event`, so one panel is open. Maps are built on `useMapView` (`src/lib/mapview.ts`) inside `MapShell.vue`, which owns the shared toggles, lock, basemap, plates, teeth and faults; a page adds its markers in the `layers` slot. Volcano state lives in `src/lib/volcanoes.ts` (`createVolcanoStore`, classification helpers, filter parsing) under the `VOLCANOES`, `SELECT_VOLCANO` and `SET_VOLCANO_FILTER` keys; selection is `?volcano=`.
- Long windows: `createCatalog` loads a range by calling `summary` first, `chooseFloor` picks the list floor from the bands (requested, else 5/6/7 within `EVENT_LIMIT`), then `events` at that floor and `grid` at the requested floor when raised; the result is `catalog.stats` (`WindowStats`), with `requested`, `floor` (effective), `raised` and `windowTotal`. `MapDensity.vue` shades `cellRing` polygons (clockwise, `src/lib/density.ts`) with no pointer events; `MagnitudeTimeChart` switches to per-bin bars and maxima when `raised`; `src/lib/eras.ts` holds the 1964/1973/1976 marks; `animation.ts` steps by `unitFor(start, end)`. Test fakes: `fakeApi` answers `summary`/`grid` for one event, `raisedApi()` overflows the budget, `makeContext({ range })` loads a window.
- Active Earth: `CombinedMap.vue` puts `MapVolcanoes` under `MapEvents` on one `MapShell`; the map logic shared by `QuakeMap`, `VolcanoMap` and `CombinedMap` lives in `src/lib/layers.ts` (`useQuakeLayer`, `useVolcanoLayer`), the replay strip in `AnimationBar.vue`, the volcano legend rows in `VolcanoLegendRows.vue`. The summary rows (`StatsStrip`, `VolcanoTiles`) and the refine bars carry a 3 px left edge in their dataset's colour (`.stats.earthquakes` / `.stats.volcanoes`, `.filters.refine` / `.volcanoes`). Both refine bars render inside `RefineBar.vue` (collapsed summary from `src/lib/refine.ts`, click-to-toggle head (`.rhead`, role button), `Hide markers` bound to `catalog.hideMarkers` / `volcanoes.hideMarkers`, in-memory refs the maps honour). Cards render inside `CardGrid.vue`, clipped to `settings.current.value.cardRows` (`src/lib/settings.ts`, `SETTINGS` key, `localStorage` `tectonic.settings`; `createSettings(null)` in tests). `NearbyQuakes` dates quakes against `eruptionAnchor` with `offsetText`.
- Marks: `src/lib/marks.ts` (`createMarks`, `MarksStore`, `MARK_TERMS`, `ALL_GROUP`; `localStorage` `tectonic.marks`, `createMarks(null)` in tests) under the `MARKS` key; `MARKS_NAV` (`MarksNav` in `keys.ts`, built in `App.vue`) is the only router access: `viewUrl` is the route minus `marks`/`show`, `overlay` reads them, `open/list/show/close/goTo` write them; `openHere(mark)` pushes `hereTarget(page, region, query, mark)` from `src/lib/marks-nav.ts` (Active Earth when the page lacks the kind's panel) and posts to the `NOTICE` store (`src/lib/notice.ts`, `createNotice`, one `role=status` strip rendered by `App.vue`). `moveGroup` orders the rail; `MarksIO.vue` at the rail's foot exports `exportDocument` as `exportFileName(now)` and imports through `parseMarks` into `merge` (`mergeDocuments`, `MergeReport`) or `replaceAll`. `MarkButton.vue` sits under both panel headers; the panel bodies are `EventDetailBody.vue` and `VolcanoDetailBody.vue` so `MarksOverlay.vue` (`MarkRow`, `MarkPanels`, `ConfirmButton`) can stack them. `MarkMatrix.vue` (with `MatrixArrow.vue`) over `src/lib/matrix.ts` (`pointOf`, `staircase`, `cardOf`, `nodeLines`, `compareTitle`) is the pairwise Compare view (`?show=matrix`): a staircase of edge cards read from the left node to the top node. Thumbnails: `MarkThumb.vue` over `src/lib/thumb.ts` and `src/lib/basemap-cache.ts` (`loadBasemapFor`, shared with `mapview.ts`; `resetMapCaches` clears it).
- Cross-section: `src/lib/section.ts` (great-circle geometry on unit vectors: `parseSection`/`sectionQuery` for the `?section=` key, `lengthKm`, `azimuth`, `projectOnto` with signed off-distance, `profileOf`, `surfacePointsOf`, `corridorRing`, `linePoints`), `src/lib/section-tool.ts` (`useSectionTool`: arm, place two points, drag an end through a draft, clear, clamp the half-width), created inside `useMapView` from the injected `SECTION`/`SET_SECTION` keys (`App.vue` owns the query key; it survives page and region switches). `MapShell` renders the `Section` button (hidden with `:section-tool="false"` on the Volcanoes page), routes svg mousedown/click to `onMapDown`/`onMapClick` (a click more than 3 px from its press is a pan, not a placement) and draws `MapSection.vue` (corridor, great-circle line, handles with pointer capture, A/A′ labels). `SectionProfile.vue` sits under the map on the Earthquakes and Active Earth pages: true-scale depth against distance, height capped at 480 px with deeper events counted in the caption, ×1/×2/×4, corridor width and Clear in its title. `invertPoint`/`projectPoint` in `geo.ts` wrap the projection so off-map points come back null or NaN. Relief along the line: `GET /api/relief?section=lon1,lat1,lon2,lat2&n=` (`routes/relief.ts`, `geo/relief.ts`: `jp2Codestream`, `placeTile`, `sampleRelief`, `reliefAlong`, `loadRelief`) samples `apps/server/data/relief/earth_relief_03m.i16`, a 7200×3600 int16 grid of metres that `pnpm --filter @tectonic/server geo:relief` (`relief-cli.ts`, OpenJPEG wasm codec as a dev dependency) builds from GMT's SRTM15+ 3′ JPEG 2000 tiles; the Dockerfile runs it, the file is gitignored, `buildApp({ reliefFile, reliefLayout })` injects a tiny grid in tests, and the route 404s without a file. Great-circle maths (`slerp`, `distanceKm`) lives in `packages/shared/src/greatcircle.ts`. `SectionProfile` fetches the relief when the ends change (not the width), draws land and water fills closed along sea level and lifts the axis above zero to the highest point.
- Space weather: the server polls NOAA SWPC (`src/space/{schema,client,parse}.ts`, eleven JSON files under `SWPC_FILES`) through four scheduler jobs in `ingest/space.ts` (`space_fast` and `space_events` every five minutes, `space_slow` hourly, `space_prune` six-hourly; `SPACE_ENABLED` and `SPACE_*_INTERVAL_MS`), no `ingest_runs` rows. One tall `space_samples(series, time, source, value)` table holds every numeric series (`SPACE_SERIES` in `packages/shared/src/space.ts`; add a series by adding an id, not a migration) beside `space_flares`, `space_alerts` and `space_scales` (one row per UTC day and kind, latest issue wins). `repositories/space.ts` upserts in place (the 1-minute Kp revises until its window closes) and `downsampleBefore` thins rows older than 30 days to 5-minute means. Routes in `routes/space.ts`: `GET /api/space/now` (latest reading per series, scales around today, newest flare and alert) and `GET /api/space/window?from=&to=` (raw up to 25 hours, else one shared `date_bin` bucket for about 1,500 points, 93 days at most). Web: `/space` is the fourth page (`Page` "space", no region, `hasVolcanoes` false, `pagePath` ignores the region); `src/lib/space.ts` (`createSpaceStore` under `SPACE`, polled every minute while the range is a window, never for a fixed one; `parseSpaceRange`/`spaceRangeQuery` for `?window=` or `?from=&to=`, `SET_SPACE_RANGE` in `App.vue`), `space-format.ts` (GOES classes, G levels, Kp thirds, alert headlines, `datetime-local` values), `space-chart.ts` (`ROWS`, domains, `linePath` with gaps, `nearestIndex`, `flareBands`, `kpBars`, `viewX`, the `RowData` model). Components: `SpacePage` (`SpaceRefine`, `SpaceTiles`, `SpaceStack` of seven `SpaceRow`s on one axis with a pointer readout and, while a past aurora frame is chosen, a dashed `.aumark` at its forecast time, rail of `SpaceForecast` and `SpaceFlares` (hover lights the band, click frames the flare); `SpaceAlerts` is a `CardGrid` row under the tiles, newest on the left, each card edged by `alertKind` and opening to its full text), `SpaceStatus` replaces `StatusLine` on that page. Test fixtures: `apps/server/test/fixtures/swpc` (trimmed live files, 2026-10-25) through `test/support/space-stub.ts`; web `test/support/space.ts` (`spaceNow`, `spaceWindow`), `makeContext({ space: true })`. Aurora: the `aurora` part of `space_fast` stores each OVATION Prime frame in `space_aurora` (a 65 160-byte `bytea` grid, longitude-major through `auroraIndex`; hemispheric power from `text/aurora-nowcast-hemi-power.txt` matched by forecast time, and every row of that file written as the series `hp_north` and `hp_south` at its forecast time, the `power` row of the stack) and prunes past `AURORA_RETENTION_HOURS` (72); `GET /api/space/aurora` lists the frames without grids, `GET /api/space/aurora/:observed` serves one with `grid` as base64, cached an hour. Web: `src/lib/aurora.ts` (`createAuroraStore` under `AURORA`, started with the space store, `select(observed | null)`, `play()`/`pause()` stepping `PLAY_STRIDE` frames every `PLAY_STEP_MS` after each grid and following live again at the end, a 160-grid cache, `bands` computed by `aurora-bands.ts` with d3-contour at `AURORA_THRESHOLDS`, pole rows pulled in to ±89.9°), `sun.ts` (`subsolarPoint`), `aurora-map.ts` (`polarProjection` noon-up, `nightRing`, `polarGraticule`, `timeMarks`); `SpaceAurora.vue` (two `AuroraMap`s, caption, scrub, Play, Latest) sits under the stack and reads the world land through `loadWorldBasemap` in `basemap-cache.ts`. Fixtures: `test/fixtures/swpc/ovation.json` and `hemi-power.txt`; web `test/support/aurora.ts` (`ringGrid`, `capGrid`, `auroraIndex`, `auroraFrame`).
- Field overlays: `apps/web/public/fields/` (four PNGs and `fields.json`, generated by `pnpm --filter @tectonic/web geo:fields` from `scripts/fields-cli.ts`, never hand-edited; sources cached in `apps/web/.cache/fields/`). The pure parts are `src/lib/field-render.ts` (lon/lat and projected grid sampling, the DDS-9 Albers forward projection, linear and equalised ramp stops, ramp-position quantisation into `BANDS`, the RGBA pixel loop) and `src/lib/gxf.ts` (Geosoft GXF reader; sense 1 puts row 0 at the south-west). Types `FieldRaster`/`FieldsFile` live in `packages/shared`. `src/lib/fields.ts` (`loadFields` once through `api.fields()`, `rasterFor`, `viewOf`) feeds `useMapView`'s `field`/`fieldRaster`/`fieldError`; `MapShell` renders the `Field` select and `MapField.vue` (an `<image>` the size of the frame between the basemap and the faults, multiply on light, plain on dark) and passes the raster to `MapLegend`'s ramp row. Global rasters are 1536 px wide, West Coast 2048. Research under `docs/research/`.
- Table filters: `src/lib/table-filters.ts` (`applyEventTableFilter`, `applyVolcanoTableFilter`, `activeEventColumns`/`activeVolcanoColumns`, `countriesOf`) over `RangeInputs.vue` and `TableFilterHead.vue`; `CatalogTable` and `VolcanoTable` keep their filter in a local ref (not the route), apply it after the store's filter and before sorting, and reset it on region change. Card detail lines (`.mcard .lines`) clamp at five.
- Touch: `src/lib/touch.ts`. The map starts locked for every pointer (`locked = ref(true)` in `useMapView`). A locked map passes only two-finger gestures to d3-zoom (`zoomAllowed`) and uses `touch-action: pan-x pan-y`; on coarse pointers `MapEvents` gets a `minRadius` floor in viewBox units (7 px over the measured css scale) and `QuakeMap` shows `TOUCH_HINTS` on a one-finger drag or a lock toggle.
- Markers: `src/lib/markers.ts` sizes epicentres and beachballs at zoom 1 from the floor in force (`QuakeMap` passes `catalog.floor` to `MapEvents` and, as `floor`, to `MapShell` for the legend); `MapEvents` divides by `k ** ZOOM_SHRINK` so they grow on screen as the map zooms.
- Subduction polarity comes from the PB2002 title slash (`src/lib/teeth.ts`, `polarity`); teeth are laid in projected space by `teethPath` and keep a constant screen size.
- Quaternary faults (West Coast view only) come from `data/geo/wc-qfaults.json`, generated by
  `pnpm --filter @tectonic/server geo:qfaults` (`src/geo/qfaults.ts` merges the USGS pieces by fault
  section, stitches ends within 50 m, simplifies and quantises). The web draws one SVG path per age and
  certainty class (`MapFaults.vue`) and finds the trace under the pointer with a d3-quadtree over the
  projected vertices (`faultIndex` in `src/lib/faults.ts`) instead of per-feature hit paths; the svg
  skips the lookup when the pointer is inside a `[data-hit]` group (plates, events).
- `.vue` files are linted type-aware through `@vue/eslint-config-typescript`; `vue-tsc` typechecks. Interfaces that tests spy on (`ApiClient`) use function-typed properties, not methods, so the unbound-method rule stays on.
- Production: `deploy/nginx.conf`, the two Dockerfiles and the compose `prod` profile. nginx serves `dist/` and proxies `/api` to the `server` container. The live site (tectonicdesk.org) runs `deploy/docker-compose.prod.yml` with Caddy for TLS on a DigitalOcean droplet; `.github/workflows/deploy.yml` builds and pushes the images to GHCR and rolls them out on every push to `release`, `ci.yml` checks pull requests into `main` and `release` (no push trigger, so a merge is checked once). Keep `main` green; releasing is a pull request from `main` into `release`.
